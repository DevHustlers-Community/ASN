# Upgrade bandit to 1.14.1 in the broker and chat service

## Change

- `services/event-broker/mix.lock`: bandit `1.14.0` → `1.14.1`.
- `services/chat-service/mix.lock`: bandit `1.13.1` → `1.14.1`, plus the
  transitive `plug_crypto` `2.2.0` → `2.2.1` that the newer release requires.
- No application code or configuration changed. Both services already declared
  `{:bandit, "~> 1.5"}`, which allows `1.14.1`.

## Why

Issue #21. `mix hex.audit` reported advisories against the locked version in
both services:

- broker, `1.14.0`: `EEF-CVE-2026-116078` (HIGH) — HTTP/2 request bodies sent
  as many 1-byte DATA frames amplify memory use. Fixed in `1.14.1`.
- chat, `1.13.1`: `EEF-CVE-2026-111101` (HIGH, chunked HTTP/1 bodies),
  `EEF-CVE-2026-114216` (MEDIUM, chunk-extension request smuggling),
  `EEF-CVE-2026-114213` (HIGH, WebSocket fragmented-message limit bypass), and
  `EEF-CVE-2026-113436` (HIGH, quadratic `Content-Length`/port parsing). All
  four are fixed in `1.14.0`.

`bandit` is the HTTP edge of both services: the broker serves its publish,
admin, and `/metrics` routes through it, and chat serves HTTP and WebSockets
through `Bandit.PhoenixAdapter`.

`1.14.0` also changes HTTP/2 defaults (500 concurrent streams, a 262144-byte
header-list limit, enforced receive windows) and `1.14.1` tightens HTTP/1
`CONNECT` and HTTP/2 header handling. Neither service sets HTTP/2 options or
terminates TLS itself, so no configuration change is required.
